# Amanat

Financial literacy for Deaf and Hard-of-Hearing children, ages 7–15.
Video-first, picture-first, and built to WCAG 2.2 AA.

Written for **Indian Sign Language (ISL)** and the **Indian rupee (₹)**.
The interface reads in **English or Hindi** — see [Languages](#languages).

## Run it

```bash
npm install
npm run dev
```

Then open the address Vite prints (usually `http://localhost:5173`).

```bash
npm run build     # produces dist/
npm run preview   # serve the built site locally
```

Deploys as a static site. `vercel.json` and `public/_redirects` already contain
the single-page-app rewrite both Vercel and Netlify need.

## What is where

```

  README.md               ← how to edit a lesson; read this first
  modules/*.json          ← the 9 lessons, each written at 3 levels

  index.js                ← loader; add new lesson files to the list here
  ISL-CLIPS.md            ← the recording brief + shot list for the 30 signs
  SCHEMES-RESEARCH.md     ← sourced facts behind the bank/scheme lessons
  sign-clips.json         ← generated by `npm run sign:sync`. Do not hand-edit.
  sign-sources.json       ← resolved Spread the Sign page per term

public/captions/          ← WebVTT caption files (placeholders for now)
public/sign/              ← the recorded ISL dictionary clips go here

scripts/sign-clips.mjs    ← scans public/sign/, writes the manifest

src/
  config/site.js          ← site name, currency, sign language, levels. One file.
  i18n/
    strings.js            ← every word of UI text, in English and Hindi
    LanguageProvider.jsx  ← the chosen language + the t() lookup
  components/
    CoverHero.jsx         ← the animated cover at the top of the home page
    LanguageToggle.jsx    ← English / हिन्दी, in the header on every page
    VideoPlayer.jsx       ← captions, speed, ISL panel, big controls
```

## Swapping in the real videos

The lessons currently point at public-domain Blender Foundation clips so the
player can be tested. For each lesson:

1. Open the lesson file in `content/modules/`.
2. In each level, set `video.src` and `video.poster`.
3. Replace `video.captions[].src` with your real `.vtt` files, placed in
   `public/captions/`.
4. Set `video.signInterpreter.src` to the ISL interpreter clip. Until you do,
   the player shows a labelled "ISL video coming soon" panel in the exact place
   the clip will appear, so the layout does not shift later.

## The ISL dictionary clips

Thirty terms. **[content/ISL-CLIPS.md](content/ISL-CLIPS.md)** covers all three
routes — sourcing from Spread the Sign (permission granted; **record its scope
at the top of that file**), sourcing from the ISLRTC dictionary, and filming the
rest — plus the shot list with the meaning each sign has to carry. No single
collection covers all thirty, so expect to do some of each.

To get a lookup link for every term still missing:

```bash
npm run sign:links
```

Save the files rather than hotlinking them: a `<video src>` pointing at someone
else's server would make every visitor call a third party, which contradicts the
privacy promise on `/accessibility`.

Everything around them is already built. Name each file after the term's id,
drop them in `public/sign/`, and run:

```bash
npm run sign:sync
```

That scans the folder, updates `content/sign-clips.json`, and prints how many of
the thirty are in place, what is still missing, and any file whose name matches
no term. Clips go live one at a time — no JSON editing, no code change, and the
Teachers page shows the running count so the gap is never hidden. `npm run
sign:check` does the same without writing, and exits non-zero while any are
missing, for CI.

A clip that lives elsewhere or is named differently can still be pointed at
directly with `signVideo.src` on the entry in `content/dictionary.json`; an
explicit path always wins over the folder.

## Languages

A toggle in the header switches the interface between English and Hindi. The
choice is remembered in `localStorage` (`amanat.lang.v1`), sets
`<html lang>`, and defaults to Hindi on a device whose browser language starts
with `hi`.

**Translated today:** the cover, the home page, the header, the footer, the
level chooser, and the nav. **Not translated yet:** the lesson content, the dictionary
entries and the Teachers and Accessibility pages — these still read in English,
and the home page says so plainly when Hindi is on rather than letting a family
find out three clicks in.

To translate a string, open `src/i18n/strings.js` and add the same key to both
`en` and `hi`. A key missing from `hi` falls back to the English text, so a
half-finished translation never blanks the screen. To add a third language, add
it to `LANGUAGES`, add its block to `strings`, and add its name for the sign
language to `signLanguage.labels` in `src/config/site.js`.

The lesson JSON in `content/` is not translated yet. When it is, the shape to
use is a language key inside each field rather than parallel files, so a lesson
stays one file.

Both typefaces carry Devanagari themselves, so Hindi needs no font substitution
— see [Fonts](#fonts).

## The cover

`src/components/CoverHero.jsx` is the first screen: a full-bleed panel over a
drifting colour field, holding the heading, three promise chips and two buttons.
One centred column, and nothing in it that is not read.

Both animations on it — the staggered reveal and the colour sweep across the
heading — are decorative. Nothing it says depends on motion, and `src/index.css`
reduces every animation to 0.01ms under `prefers-reduced-motion`, which lands
them on their finished state. The tokens live in `tailwind.config.js` under
`keyframes`/`animation`.

The rest of the home page follows one rule: **a box means you can click it.**
Everything that is only read sits on the page with no border or tint around it,
separated by space and type size. That is Mayer's coherence principle — people
learn more when extraneous material is removed — and it is the reason not to
reintroduce cards as "polish".

## Progress storage

Progress lives in `localStorage` under `amanat.progress.v1`. There is no
backend, no login and no analytics. The Teachers page can export it to a JSON
file and erase it.

## Fonts

**Mukta** for reading, **Baloo 2** for headings and buttons. Both are by
Ek Type in Mumbai, and both were drawn for Devanagari and Latin as one design —
so switching to Hindi changes the script, not the typeface, and the two scripts
share a baseline, a weight and a colour on the page.

Both are bundled from `node_modules` via `@fontsource`, imported at the top of
`src/main.jsx`. Nothing is fetched from a font CDN, because the site promises
that opening it sends nothing to a third party. Each file carries a
`unicode-range`, so a reader in English never downloads the Devanagari.

Verdana and Nirmala UI remain in the stack underneath, for a device that blocks
web fonts entirely.

This replaced Atkinson Hyperlegible, which the stylesheet used to name but which
was never actually present in the repo — the site had been rendering in Verdana.
If you want Atkinson's letterform disambiguation back for the body text, put it
first in `fontFamily.sans` and self-host it the same way; note that it has no
Devanagari, so Hindi would fall through to Mukta and the two languages would no
longer match.

## Accessibility

Every colour in `tailwind.config.js` carries its measured contrast ratio in a
comment beside it. The ratios were computed with a WCAG contrast function rather
than estimated, and a live audit of the rendered pages (home, dictionary,
teachers, accessibility, a learning path and a lesson, in both languages) found
no text below 4.5:1 and no icon below 3:1.

The palette is also simulated for colour-vision deficiency — deuteranopia,
protanopia and tritanopia, using the Machado/Oliveira/Fernandes matrices — and
graded on CIELAB separation. Roughly 1 man in 12 has some CVD, so a palette that
only passes contrast is only half checked. Colours that carry meaning against
each other (success against error, above all) are held apart under every CVD
type; colours that are merely decorative are allowed to converge, because no
state in this UI is signalled by hue alone.

`/accessibility` in the running site is the statement written for teachers and
families.
